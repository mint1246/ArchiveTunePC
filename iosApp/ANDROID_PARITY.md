# Android parity inventory

This is a source inventory, not a parity certification. Android has configurable layouts, account-dependent content and device-dependent insets; exact rendered geometry and colors must be checked against the same Android settings and viewport in screenshots. The iOS implementation is incomplete. Shared screens and services below have host-side validation; this does not establish native behavior, visual parity or feature parity. The requirement remains exact Android appearance and behavior, with no intentional iOS redesign.

## Shell and theme

- [MainActivity.kt](../app/src/main/kotlin/moe/rukamori/archivetune/MainActivity.kt) renders a scrolling/collapsing `TopAppBar`: a 35 dp `about_appbar` mark with 3 dp end padding, then bold `titleLarge` “ArchiveTune”. Android adds History, News, New releases and Settings actions (including badges/tooltips), and uses a status-bar gradient when configured. The app-bar content height constant is 64 dp, excluding system inset ([Dimensions.kt](../app/src/main/kotlin/moe/rukamori/archivetune/constants/Dimensions.kt)). All four actions are wired to History, News, New release albums and Settings. Collapsing behavior, badges and full secondary-screen layouts remain incomplete.
- [FloatingNavigationToolbar.kt](../app/src/main/kotlin/moe/rukamori/archivetune/ui/component/FloatingNavigationToolbar.kt), [Screens.kt](../app/src/main/kotlin/moe/rukamori/archivetune/ui/screens/Screens.kt), [Dimensions.kt](../app/src/main/kotlin/moe/rukamori/archivetune/constants/Dimensions.kt): Android phone destinations are Home, Search, Library, Friends. Equal-width Material short navigation items show icons and labels, with active/inactive icon crossfade; Search supports double-tap. Container is `surfaceContainer`, 78 dp high, max-width constrained, 32 dp standalone corners, joining a mini player with 12 dp junction and 28 dp outer corners. Tablet/TV differ. The shared shell uses all four destinations and the Material short navigation component with Android dimensions and copied icon assets. Search double-tap, tab fades, detail push/pop, navigation spring/slide and selected-tab scroll-to-top now have source-derived implementations. Native captures still show differences; this is not a motion-parity result.
- [Type.kt](../app/src/main/kotlin/moe/rukamori/archivetune/ui/theme/Type.kt), Android theme sources and user settings define typography, Material color and shapes. Dynamic/pure-black/artwork backdrop and accessibility/display options affect appearance. The shared theme uses the Android Poppins font, expressive Material theme and shapes. Light/dark reference role colors were exported from the Android 16 reference emulator. The artwork shader now uses the Android noise/saturation/brightness/vignette values and the same three radius-four box-blur passes. Artwork palette extraction and glass roles now use a portable AndroidX quantizer and vendored Material color utilities. The quantizer passed 75 ordered-output comparisons against the AndroidX Java source. Per the user’s subsequent correction, artwork-mode text/foregrounds are white. Pure-black/custom controls and full settings remain incomplete. Fresh native captures are in build/parity/motion-review.

## Home

Never substitute fabricated content for absent data.

## Library

Its horizontally scrolling filters/pages include Library, Playlists, Podcasts, Spotify (conditional), Songs, Artists and Albums, with optional playlist tags and refresh/sync behavior. The default Library page is [LibraryMixScreen.kt](../app/src/main/kotlin/moe/rukamori/archivetune/ui/screens/library/LibraryMixScreen.kt); the other pages have their own sort, item, and navigation actions. The shared Library now has local liked songs, playlists, song filters, sorting and list/grid views, plus playlist create/rename/delete and ordered song additions/removals preserving duplicates. Account library sync/mutations, Podcasts, Spotify, Artists/Albums collections, tags, downloads and local media remain incomplete. Local Library layouts are not yet certified against simulator captures.

The shared V4 player has seek/previous/play/next, favorite, queue selection/removal, shuffle/repeat, radio queues, timed lyrics, sleep timer and speed controls. Radio begins the clicked song immediately, keeps that identity over server selection, and fills the queue without restarting audio. UIKit sharing and AVPlayer speed integration now compile in the native app; their full interactive acceptance checks remain incomplete. Animated artwork backdrop is implemented with Skia. Exact player geometry, slider treatment, gestures, full menus, timer dialog, downloads, artist/album actions, alternate Android player designs and rich lyrics remain incomplete. Native AVPlayer transport now starts and advances after enabling macbox’s previously disabled virtual audio device. A doubled displayed native duration is under investigation; no audible-output or playback-parity certification is made. Live lyrics load. The player is removed from the active layout while lyrics or queue is open, and the parent sheet drag is disabled in those overlays.

## Cross-cutting missing major features

Implemented services include remote artist/album/playlist browsing, local recent-play history, Android News feeds and a Discord exchange/friend-list flow with strict nonce-bound callbacks. The iOS WebKit login sheet compiles but actual sign-in remains unverified; social tokens currently remain in memory. Google/YouTube login/session renewal, Keychain storage, authenticated sync/mutations, download/offline playback, local scanning, podcasts, Spotify integration, full Friends/chat/presence, statistics, Play Together, complete settings/personalization, audio effects and other exposed Android features remain required parity work. Android-specific OS integrations need iOS equivalents where applicable. Verify each feature and state end-to-end on a real iOS device; JVM compilation or a matching static screen cannot establish feature parity.
